## 2. Refactoring plan

### 2.1 Conventions
- **Python:** ruff (lint + format, line length 110), type hints on public functions, `logging.getLogger(__name__)`, no `print`, no imports inside functions, pyright in basic mode.
- **JS:** oxlint with warnings as errors, Prettier, function components, hooks for stateful logic, named exports for `lib/`, kebab-free PascalCase component files.
- **Naming:** keep the API field `provider` for compatibility, but treat it as the *model setting* (`"per-agent"` or a model id). New code says `model`, not `provider`.

### 2.2 Config and env
- `config.py` reads env (and `backend/.env`, resolved relative to the file, not the current directory) via pydantic-settings only. No more `os.getenv` defaults.
- Remove the dead `GROQ_API_KEY`/`GEMINI_API_KEY`. Add `CORS_ORIGINS` (comma list), model settings (§3), limits (§2.4), `MAX_REVISIONS`, `SEARCH_PROVIDER` (`auto` = Tavily if key else ddgs, `off` = no web search; used for offline dev and e2e).
- `.env.example` documents every variable. The frontend gets `.env.example` with `VITE_API_BASE_URL`.

### 2.3 Error handling
- One LLM entry point `llm.invoke(kind, messages, model=None) → (text, model_used)`. It raises `LLMUnavailable(reason)` with `RATE_LIMITED`, `DAILY_LIMIT` or `ALL_FAILED` after the chain is exhausted.
- Nodes record `status` (`completed` / `no_results` / `degraded` / `failed`), `error`, `model_used` in `agent_outputs`. That reaches the SSE `details` and DB logs, which fixes the badges (B10).
- Chat runs the LLM in a worker thread (`asyncio.to_thread`) so it never blocks the server.
- API errors are always `{"detail": "..."}` with the right status (400/404/409/413/422/429). The frontend shows them in an inline `ErrorNotice` with a retry button.

### 2.4 Abuse protection (✅ requested)
- Per-IP sliding-window limits (in memory, no dependency): `RESEARCH_RATE_LIMIT_PER_HOUR=6`, `CHAT_RATE_LIMIT_PER_MIN=10`, returning **429** with `Retry-After`.
- `MAX_CONCURRENT_RUNS=3` globally, returning 429 "busy".
- Length caps: query 4–2000 chars, chat message 1–2000 chars (422).
- **Model allowlist:** the API only accepts models from `MODEL_OPTIONS`. Today any string is accepted, so a caller could pick a *paid* model on your key, or a >50-char id that crashes Postgres' `VARCHAR(50)`.
- CORS from `CORS_ORIGINS`, no `"*"`.
- Render start command gets `--proxy-headers --forwarded-allow-ips="*"` so the limiter sees real client IPs.
- `shortcut:` comment noting that in-memory limits are per process; upgrade to Redis if you ever run more than one instance.

### 2.5 Dead code and duplication
- Delete everything listed as dead in ANALYSIS §6.
- One model catalogue (backend `config.py`, served by `/api/models`; the frontend never hard-codes models).
- One agent catalogue (`lib/agents.js`).
- One gatherer helper in `nodes.py`.
- One `get_report(run_id)` query helper.
- Remove the unused deps `langchain`, `langchain-groq`, `langchain-google-genai`, `clsx`, `tailwind-merge`.

## 3. Model routing (✅ requested)

Two modes, chosen per run from the Composer:

**Per-agent kinds.** Each kind of agent in the hierarchy shares one primary model:

| Kind | Agents | Setting | Default primary |
|---|---|---|---|
| Supervisor | planner | `PLANNER_MODEL` | `nvidia/nemotron-3-ultra-550b-a55b:free` |
| Specialists | data analyst *(researcher and news agent are search tools and make no model calls)* | `SPECIALIST_MODEL` | `nvidia/nemotron-3.5-lightning:free` |
| Reviewers | verifier, critic | `REVIEWER_MODEL` | `google/gemma-4-31b-it:free` |
| Writers | writer, report chat | `WRITER_MODEL` | `nvidia/nemotron-3.5-super-vl:free` |

**One model for all agents.** A second dropdown lists `MODEL_OPTIONS` (the live free models). It defaults to `DEFAULT_MODEL=nvidia/nemotron-3-ultra-550b-a55b:free`.

**4-tier fallback (both modes):** `[primary, SECONDARY_MODEL, THIRD_MODEL, FALLBACK_MODEL]`, with duplicates removed. Defaults: `google/gemma-4-31b-it:free` → `nvidia/nemotron-3.5-super-vl:free` → `openrouter/free`.
- It moves to the next model on any error or empty reply.
- HTTP 429 marks the run as rate-limited, and "per-day" in the error marks the daily limit, so the error message tells you which.
- `max_retries=0` and a 90 s timeout per call, so a dead model costs seconds, not minutes.
- The mode and model you picked are remembered in the browser.
- Report chat uses the **writer** chain, or your single model if the run used single mode.
- With no `OPENROUTER_API_KEY`, every kind uses the offline mock. It now returns valid JSON per agent, so the demo and tests exercise the real flow, and the UI shows an "Offline demo mode" banner.

`GET /api/models` returns `{llm_configured, default_mode, default_model, options[], kinds[{kind, label, agents, model}], fallbacks[]}`. The inspector shows **which model actually answered** each agent.

## 4. UI/UX redesign

### 4.1 Direction: "the research desk"
**Who:** someone with a real question who wants a sourced brief they can trust, and who checks *how* the agents got there.
**Feel:** an editorial fact-checking desk. Calm, precise, paper-and-ink, with footnotes. Not a neon AI console.

- **Domain:** assignment desk, wire copy, fact-check, copy desk, editor's red pencil, footnotes, dossier, routing slip, galley proof.
- **Colour world:** newsprint off-white, carbon ink, blue copy-editing pencil, editor's red pencil, manila tan, archival grey.
- **Signature, the Routing Slip:** the pipeline drawn as the slip clipped to a manuscript as it passes desks. Numbered rows: Planner → Researcher ∥ Data Analyst ∥ News → Verifier → Writer ⇄ Critic. Each row carries a status stamp, the model that worked it (mono), elapsed time and output count. A critic REVISE shows as a red-pencil "returned to writer" loop mark. Footnote-style citation chips `[1]` in the report jump to the numbered source list.
- **Rejected defaults:**
  - neon glass gradients → paper/ink surfaces with one accent;
  - a 9-tab bar → the slip *is* the navigation (click a desk to read its output);
  - a marketing hero → a compact assignment composer that collapses into a one-line brief once a run starts;
  - Inter everywhere → a sans for UI plus an editorial serif for the report.

## 7. Testing strategy

**No test makes a real AI call or touches Neon.** `conftest.py` sets env before importing the app: empty key, temp SQLite, `SEARCH_PROVIDER=off`. It also patches `ChatOpenAI.invoke` and `DDGS` to raise if anything slips through.

- **Backend (pytest + FastAPI TestClient).** `BackgroundTasks` run inside the request in TestClient, so a whole run completes deterministically.
  - Fixtures: `fake_llm({kind: reply})` and `fake_search(results)`.
  - Coverage areas: API contract, graph routing and the revision loop, node outputs, the 4-tier chain (fail → next, empty → next, 429/daily detection), JSON parsing, search tools, SSE replay/close, rate limits, serialisers, chat edit + undo, delete, startup recovery.
- **Phase 3 characterization:** tests pin today's behaviour. Known bugs are written as `xfail(strict=True, reason="B2 …")`, so each fix flips them to passing and they stay as regression tests.
- **Frontend (Vitest + Testing Library + jsdom).**
  - `lib/format` and `lib/agents`
  - `api.js` with mocked `fetch`
  - `ModelPicker` (mode switch shows/hides the model dropdown)
  - `RoutingSlip` (status from events)
  - `ReportChat` (send / edit banner / error / undo)
  - `RunPage` with a fake `EventSource` (replay, completion, reconnect)
  - `ThemeToggle`
- **E2E (Playwright, using your installed Microsoft Edge with `channel: 'msedge'`, so no browser download).** Starts its own offline backend (:8799, mock LLM, search off) and Vite (:5199). Covers: submit → live slip → report → chat → history → delete; theme toggle; **no horizontal overflow at 390 / 820 / 1440**; zero console errors. Screenshots go to `docs/screenshots/`.
- **Gates (Phase 5):**
  - backend: `ruff check`, `ruff format --check`, `pyright`, `pytest --cov`
  - frontend: `oxlint --deny-warnings`, `prettier --check`, `vitest run --coverage`, `vite build`, `playwright test`
